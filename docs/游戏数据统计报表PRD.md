# 游戏数据统计报表 PRD

| 项目 | 内容 |
| --- | --- |
| 产品模块 | 游戏管理 / 游戏数据报表 |
| 文档版本 | V1.0 |
| 更新日期 | 2026-09-03 |
| 面向角色 | 游戏运营、数据运营、游戏平台主管、财务复核人员 |

## 1. 产品概述

游戏数据统计报表用于按区域、游戏及用户维度查看游戏资金与参与情况，帮助运营人员识别不同游戏、区域和用户的投入、出奖、盈亏与返奖率表现，并进一步定位到单个游戏的用户排行。

本模块为内部运营数据工具，不面向普通用户。页面重点支持“筛选—查看汇总—定位明细—查看单游戏用户排行”的分析路径。

### 1.1 需求背景

在多厂商、多游戏、多区域的游戏运营场景中，单纯查看总投入或总出奖无法判断资金表现来自哪个游戏、哪个区域或哪些用户。运营人员需要先在统一口径下筛选游戏范围，再查看游戏与用户维度的明细，快速识别高投入用户、返奖率异常及盈亏变化。

本报表通过统一展示用户投入、用户出奖、盈亏、返奖率、游戏次数与游戏排行，为日常运营复盘、区域对比和单游戏排查提供数据入口。

## 2. 目标与范围

### 2.1 产品目标

1. 支持按区域、游戏和统计日期快速定位游戏数据。
2. 支持跨厂商、单厂商及单游戏三种游戏范围，满足不同分析颗粒度。
3. 同时提供游戏汇总和用户-游戏明细，避免用户多款游戏数据被错误合并。
4. 支持从游戏汇总进一步查看该游戏的用户排行，并通过分页控制明细阅读密度。

### 2.2 本期范围

- 总览报表
- 游戏用户列表
- 游戏选择器与游戏资料悬浮说明
- 单游戏用户排行弹窗
- 查询、重置、刷新、排序、分页、加载态与空态

### 2.3 非本期范围

- 导出报表或导出用户表
- 游戏区域资金统计独立面板
- 用户最近游戏时间字段
- 按返奖率排序

## 3. 用户角色与使用场景

| 角色 | 核心诉求 | 典型操作 |
| --- | --- | --- |
| 游戏运营 | 判断游戏及区域的资金表现 | 筛选游戏、区域和日期，查看汇总指标及用户排行 |
| 数据运营 | 定位用户在不同游戏中的投入与出奖 | 在游戏用户列表中按字段排序、翻页、查看用户-游戏记录 |
| 游戏平台主管 | 查看单款游戏内的核心用户及资金结构 | 从游戏汇总点击“用户明细”，查看单游戏用户排行 |
| 财务复核人员 | 核对投入、出奖、盈亏及返奖率口径 | 基于统一公式查看报表与明细 |

## 4. 信息架构

```text
游戏数据报表
├── 总览报表
│   ├── 筛选区：区域 / 游戏 / 统计日期
│   ├── 核心指标：活跃游戏用户、用户投入、用户出奖、盈亏、返奖率
│   └── 游戏汇总数据：游戏维度数据 + 用户明细入口
└── 游戏用户列表
    ├── 筛选区：用户 ID 或昵称 / 区域 / 游戏 / 统计日期 / 排序方式
    └── 游戏用户明细：用户-游戏粒度的列表与分页

游戏汇总数据
└── 用户明细
    └── 单游戏用户排行弹窗：排序、指标汇总、用户列表、分页
```

## 5. 统一数据口径

| 字段/指标 | 定义 | 展示规则 |
| --- | --- | --- |
| 活跃游戏用户 | 统计范围内产生任意游戏流水的去重用户数；不受游戏次数或流水金额大小影响 | 整数，千分位分隔 |
| 用户投入 | 用户在统计范围内的游戏投入金币总额 | 金币图标 + 数值；完整金额下方可辅助显示“万/亿”单位 |
| 用户出奖 | 用户在统计范围内获得的游戏出奖金币总额 | 金币图标 + 数值 |
| 盈亏 | `用户投入 - 用户出奖` | 正值正常展示；负值显示负号、红色文字和亏损金额 |
| 返奖率 | `用户出奖 ÷ 用户投入 × 100%` | 保留 2 位小数；当用户投入为 0 时显示 `--` |
| 游戏次数/下注次数 | 用户在指定游戏、统计范围内产生的游戏参与次数 | 整数，千分位分隔 |
| 游戏排行 | 当前筛选结果中，按用户投入从高到低生成的用户-游戏记录排名 | 不因列表排序方式改变而改变 |

## 6. 功能需求

### 6.1 页面公共结构

1. 页面名称为“游戏数据报表”，面包屑为“首页 / 游戏管理 / 游戏数据报表”。
2. 提供“总览报表”和“游戏用户列表”两个标签页，切换后保留当前业务上下文；区域已选定时切换到用户列表应同步带入区域条件。
3. 页面提供刷新入口，刷新时展示加载状态，完成后给予“数据已更新”反馈。

### 6.2 区域筛选

1. 区域可选：全部区域、阿拉伯、土耳其、印度、印尼、巴基斯坦、孟加拉、菲律宾、巴西、其他。
2. 默认选中“全部区域”。
3. 区域以用户既有的区域归属字段为准；选择具体区域后，总览数据、游戏汇总和游戏用户列表均只展示该区域范围内的数据。
4. 清空或重置后恢复“全部区域”。

### 6.3 游戏筛选

#### 6.3.1 游戏范围

游戏选择器必须支持以下四种筛选方式：

| 类型 | 选择值 | 统计范围 |
| --- | --- | --- |
| 跨厂商全部游戏 | 全部游戏 | 热游与灵仙旗下全部游戏 |
| 热游全部游戏 | 热游 · 全部游戏 | 仅热游旗下全部游戏 |
| 灵仙全部游戏 | 灵仙 · 全部游戏 | 仅灵仙旗下全部游戏 |
| 单项游戏 | 具体游戏名称 | 仅该游戏 |

1. 默认选择“热游 · 全部游戏”。
2. 游戏选择器顶部需提供“全部游戏”入口，并明确说明其汇总热游与灵仙的全部游戏。
3. 厂商切换区域包含“热游”“灵仙”两个选项；在对应厂商下，支持选择该厂商全部游戏或任一单项游戏。
4. 游戏目录至少支持 50 个游戏；每项展示游戏图标、游戏名称、游戏 ID 和所属厂商。
5. 支持按照游戏名称或完整游戏 ID 搜索并单选游戏。
6. 当前选择为单项游戏时，触发器显示该游戏图标和名称；当前选择为全部游戏时，显示对应的汇总名称。

#### 6.3.2 游戏资料说明

1. 游戏名称旁提供问号入口。
2. 鼠标悬浮或键盘聚焦后展示浮层，包含游戏图标、游戏名称、游戏 ID、游戏厂商。

### 6.4 统计日期

1. 支持选择统计日期范围，当前展示格式为 `YYYY-MM-DD - YYYY-MM-DD`。
2. 所有指标、汇总与明细均以当前统计范围为准。
3. 单游戏用户排行弹窗展示当前统计日期/范围，确保用户知道排行数据口径。

### 6.5 总览报表

#### 6.5.1 筛选与操作

1. 筛选项：区域、游戏、统计日期。
2. 操作项：查询、重置。
3. 查询后更新核心指标和游戏汇总数据；重置恢复默认筛选条件。

#### 6.5.2 核心指标

总览需要展示以下 5 个指标：

| 指标 | 辅助说明 |
| --- | --- |
| 活跃游戏用户 | 统计周期内产生任意游戏流水的去重用户数 |
| 用户投入 | 用户实际投入金额 |
| 用户出奖 | 游戏返奖/派奖金额 |
| 盈亏 | 用户投入 - 用户出奖 |
| 返奖率 | 用户出奖 ÷ 用户投入 × 100% |

#### 6.5.3 游戏汇总数据

| 字段 | 说明 |
| --- | --- |
| 游戏 | 游戏图标、名称及游戏资料入口 |
| 区域 | 当前记录所属区域 |
| 活跃用户 | 当前游戏和区域范围内的去重活跃用户数 |
| 游戏次数 | 当前游戏和区域范围内的游戏参与次数 |
| 用户投入 | 该游戏的投入总额 |
| 用户出奖 | 该游戏的出奖总额 |
| 盈亏 | 投入减出奖后的金额 |
| 返奖率 | 出奖除以投入后的百分比 |
| 操作 | “用户明细”，打开该游戏的用户排行弹窗 |

1. 表格按当前筛选条件展示数据，空结果时提示用户调整筛选或清除筛选。
2. 不展示用户信息、热度、导出操作等已移除字段。

### 6.6 游戏用户列表

#### 6.6.1 筛选条件

| 条件 | 规则 |
| --- | --- |
| 用户 ID / 昵称 | 支持按完整或部分用户 ID、昵称查询 |
| 区域 | 与总览使用同一地区枚举 |
| 游戏 | 使用统一游戏选择器，支持全部游戏、厂商全部游戏及单项游戏 |
| 统计日期 | 按当前日期范围统计 |
| 排序方式 | 见下表 |

排序方式必须支持高到低和低到高两种顺序：

- 用户投入高到低 / 低到高
- 用户出奖高到低 / 低到高
- 盈亏高到低 / 低到高
- 游戏次数高到低 / 低到高

1. 默认排序为“用户投入高到低”。
2. 不提供按返奖率排序。
3. 在可用宽度不足时，排序方式、查询和重置应自动换行，不能被挤出可视区域。

#### 6.6.2 列表字段与行粒度

| 字段 | 说明 |
| --- | --- |
| 游戏排行 | 根据用户投入金额降序生成 |
| 用户 ID | 用户唯一标识 |
| 昵称 | 用户昵称 |
| 区域 | 用户所在区域 |
| 游戏 | 对应单项游戏信息 |
| 活跃天数 | 用户在该游戏中的活跃天数 |
| 游戏次数 | 用户在该游戏中的参与次数 |
| 用户投入 | 用户在该游戏内的投入金额 |
| 用户出奖 | 用户在该游戏内的出奖金额 |
| 盈亏 | 用户在该游戏内的盈亏 |
| 返奖率 | 用户在该游戏内的返奖率 |

1. 一行数据代表“一个用户 + 一款游戏 + 当前统计范围”的聚合结果。
2. 同一用户在统计范围内参与 10 款游戏时，应展示 10 条对应记录，不应合并为一条用户总计。
3. 列表不展示最近游戏时间字段。
4. 列表顶部不单独展示“查询用户数”；结果数量统一在分页区展示。

#### 6.6.3 分页

1. 每页展示 8 条记录。
2. 分页区展示“共 N 条 | 8 条/页”。
3. 页码较多时使用省略号分页，例如 `1 2 3 4 … 38`，避免长页码挤压说明文字。
4. 切换筛选、排序或标签页后自动回到第 1 页。

### 6.7 单游戏用户排行弹窗

1. 点击总览表格中的“用户明细”打开弹窗。
2. 弹窗标题格式为“{游戏名称} 用户游戏排行”，副标题展示游戏 ID 和游戏厂商。
3. 支持在弹窗内选择排序字段：游戏下注次数、用户投入、用户出奖、盈亏、返奖率；并支持升序、降序。
4. 弹窗顶部展示：统计日期、用户总数、当前排序字段和顺序。
5. 展示以下汇总指标：游戏下注次数、用户投入、用户出奖、盈亏、返奖率。
6. 用户列表字段：用户信息、游戏下注次数、用户投入、用户出奖、盈亏、返奖率。
7. 弹窗列表每页展示 8 位用户；底部展示总条数、页码和关闭按钮。
8. 切换排序字段、排序顺序或打开另一款游戏时，自动回到第 1 页。
9. 支持关闭按钮、遮罩点击和 `Esc` 键关闭；关闭后恢复页面滚动。

## 7. 状态与异常处理

| 状态 | 页面表现 |
| --- | --- |
| 查询中 | 列表区域显示加载状态，避免误判为无数据 |
| 无结果 | 展示“未找到匹配数据”，提供清除筛选入口 |
| 无用户数据 | 弹窗显示“暂无符合条件的用户” |
| 金额为负 | 盈亏使用红色与负号展示亏损金额 |
| 投入为 0 | 返奖率显示 `--`，不执行除零计算 |
| 游戏搜索无结果 | 提示“未找到匹配的游戏 ID 或名称” |

## 8. 验收标准

1. 可从总览和游戏用户列表中选择“全部游戏”“热游 · 全部游戏”“灵仙 · 全部游戏”及任一单项游戏，数据范围随选择变化。
2. 输入游戏名称或完整游戏 ID 能定位并选择对应游戏。
3. 选择具体区域后，总览表和游戏用户列表均仅展示对应区域数据。
4. 游戏用户列表中同一用户的多款游戏必须拆分为多条记录。
5. 用户列表支持投入、出奖、盈亏、游戏次数的双向排序，且不提供返奖率排序。
6. 负盈亏以负号和红色展示；返奖率按统一公式计算。
7. 主列表和单游戏排行弹窗均支持分页；页码较多时不得导致说明或按钮挤压变形。
8. 单游戏排行弹窗切换排序后展示正确的排序结果，并自动回到第一页。
9. 已移除功能不得在页面中重新出现：导出、热度、最近游戏时间、区域资金统计面板。

## 9. 已确认数据规则与暂不处理项

1. **统计数据存储**：统计明细永久存储，关键查询字段建立索引，保证历史范围查询的可用性。
2. **区域归属**：以用户既有的区域归属字段作为统计和筛选依据，不再按注册区域、IP 区域或最近活跃区域二次推导。
3. **特殊流水**：当前不存在取消、退款、人工补单等特殊流水场景；投入、出奖与盈亏仅按正常游戏流水计算。
4. **返奖率超 100%**：本期仅按公式正常展示，暂不增加业务解释、预警阈值或异常处理规则。
5. **游戏目录统计**：游戏目录、厂商归属及游戏 ID 在页面加载时进行统计与加载；用户点击“刷新数据”后重新执行统计。
